In-app help

The help pages are these docs: every file in docs/ is embedded into the binary at build time, so the TUI help, mnnn help and the Markdown files never diverge.

In the TUI

Open with ?, F1 or Help ▸ Help topics; Help ▸ Search help… opens straight into search and Help ▸ Keybindings shows the key reference. Help opens on the topic for what you are doing: the export dialog opens export, the keys dialog keys, the theme dialog themes, an open menu menus, otherwise TUI.

key action
Tab / → , Shift-Tab / ← select the next / previous link
Enter follow the selected link
Backspace / Alt-← back (history is shown on the right)
/ search from any topic: type to filter, results update as you type; ↑/↓ and Enter to open, Esc stops searching
i index (documentation home)
r show the Markdown source (raw); r again renders it
↑/↓, PgUp/PgDn, Home scroll
Esc, q, F1 close

A key bar along the bottom of the help popup lists these shortcuts; while searching it switches to the search keys. Every button in it is clickable.

With the mouse: click a link to follow it, click a search result or a history entry (on the right) to open it, click the search box to start searching, and [X] closes. Selecting a link with Tab scrolls it into view.

Search matches titles and bodies (substring); titles also match fuzzily, so bckprcv finds "Backup and recovery". Topics are rendered Markdown in the active theme's colours: headings, bold and italic, code and code blocks, lists, block quotes, tables (cells wrap to fit), rules, and links (other topics are selectable; web links show their URL in <…>). r switches to the raw source and back.

On the command line

mnnn help                 # list topics
mnnn help keys            # print a topic
mnnn help services/redis
mnnn help --search shard  # topics matching a query

See also command line.
