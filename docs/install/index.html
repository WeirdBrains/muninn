Install

Every package ships a prebuilt mnnn binary: no Rust or other toolchain is needed to install. SQLCipher and OpenSSL are compiled into the binary, so the only runtime dependencies are the C runtime: glibc 2.39 or newer and libgcc (Linux: Ubuntu 24.04+, Debian 13+, Fedora 40+, Arch; older systems such as Ubuntu 22.04 or Debian 12 need a source build), the system libraries (macOS), nothing extra (Windows). Downloads are on the GitHub Releases page with a SHA256SUMS file. Packaging files live in packaging/.

Building code spaces is optional and needs extra tools that the packages do not bundle: cargo (from rustup) for math, Polars, Rust and Python; Python is translated in process, so no Python install is needed. See code spaces.

Getting a release

Each release is built and checked locally, and its files are attached to its page under GitHub Releases. The latest is v2.20.0. Every release has 14 files:

File (v2.20.0) For
muninn-2.20.0-x86_64-unknown-linux-gnu.tar.gz, muninn-2.20.0-aarch64-unknown-linux-gnu.tar.gz any Linux
muninn-2.20.0-x86_64-apple-darwin.tar.gz, muninn-2.20.0-aarch64-apple-darwin.tar.gz macOS (Intel, Apple silicon)
muninn_2.20.0-1_amd64.deb, muninn_2.20.0-1_arm64.deb Debian, Ubuntu
muninn-2.20.0-1.x86_64.rpm, muninn-2.20.0-1.aarch64.rpm Fedora, RHEL
muninn-bin-2.20.0-1-x86_64.pkg.tar.zst, muninn-bin-2.20.0-1-aarch64.pkg.tar.zst Arch Linux
muninn-2.20.0-x86_64-pc-windows-gnullvm.zip, muninn-2.20.0-aarch64-pc-windows-gnullvm.zip Windows (x64, arm64)
muninn-2.20.0-packaging.tar.gz the Homebrew formula, Arch PKGBUILD and winget manifests, with this release's checksums filled in
SHA256SUMS checksums for all of the above

Download from the command line and check it, for example:

ver=2.20.0
base=https://github.com/WeirdBrains/muninn/releases/download/v$ver
curl -LO $base/muninn-$ver-x86_64-unknown-linux-gnu.tar.gz -LO $base/SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS      # macOS: shasum -a 256 --ignore-missing -c SHA256SUMS

On Windows (PowerShell) see Windows below.

(gh release download v2.20.0 does the same if you have the GitHub CLI.) Muninn is BSD-3-Clause licensed; every package carries the LICENSE.

Installing or uninstalling never touches your data in ~/.muninn (or MUNINN_HOME); delete that folder yourself to remove it.

Release tarball (any Linux or macOS)

t=x86_64-unknown-linux-gnu     # or aarch64-unknown-linux-gnu, x86_64-apple-darwin, aarch64-apple-darwin
tar -xzf muninn-2.20.0-$t.tar.gz
mkdir -p ~/.local/bin ~/.local/share/man/man1
install -m755 muninn-2.20.0-$t/mnnn ~/.local/bin/mnnn
cp muninn-2.20.0-$t/man/*.1 ~/.local/share/man/man1/

If mnnn is not found afterwards, ~/.local/bin is not on your PATH (the default on macOS and on some Linux images): add export PATH="$HOME/.local/bin:$PATH" to ~/.zshrc or ~/.bashrc and open a new terminal.

macOS: the binary is not notarized. Downloaded with curl it runs as is; downloaded in a browser, Gatekeeper blocks it ("cannot be opened"), so clear the flag first: xattr -d com.apple.quarantine muninn-2.20.0-$t.tar.gz (before extracting) or xattr -d com.apple.quarantine ~/.local/bin/mnnn.

Uninstall: remove ~/.local/bin/mnnn and ~/.local/share/man/man1/mnnn*.1.

Arch Linux

From a checkout (works today, needs Rust):

git clone git@github.com:WeirdBrains/muninn.git && cd muninn/packaging/arch
makepkg -si            # builds the committed checkout, installs package "muninn"

Prebuilt (muninn-bin, no Rust): install the release's ready-made package:

sudo pacman -U muninn-bin-2.20.0-1-x86_64.pkg.tar.zst     # or …-aarch64.pkg.tar.zst

Or build it yourself from the release's PKGBUILD (packaging/arch/PKGBUILD in muninn-2.20.0-packaging.tar.gz, which has the checksums filled in) with makepkg -si. If muninn-bin is in the AUR when you read this, yay -S muninn-bin or paru -S muninn-bin installs the same package.

Both install /usr/bin/mnnn, man pages and /usr/share/doc/muninn. Uninstall: sudo pacman -R muninn (or muninn-bin). Remove an earlier cargo install first (cargo uninstall muninn), or ~/.cargo/bin/mnnn may shadow the package, depending on your PATH.

Build and install from a checkout in one step: packaging/arch/build-local.sh builds muninn-bin from the current checkout (no download) and installs it with sudo pacman -U --needed. --source builds packaging/arch/PKGBUILD (package muninn) instead, --no-install only builds into target/pkg/arch/. If namcap is installed it lints the package first; it is optional and never blocks the install.

Debian / Ubuntu

sudo apt install ./muninn_2.20.0-1_amd64.deb      # arm64: muninn_2.20.0-1_arm64.deb

Needs Ubuntu 24.04+ or Debian 13+ (glibc 2.39); on Ubuntu 22.04 it installs but mnnn fails with GLIBC_2.38' not found. Uninstall: sudo apt remove muninn. Maintainers build it with cargo deb (packaging/debian/README.md).

Fedora / RHEL

sudo dnf install ./muninn-2.20.0-1.x86_64.rpm     # or muninn-2.20.0-1.aarch64.rpm

Requires glibc (detected from the binary). Uninstall: sudo dnf remove muninn. Maintainers build it with cargo generate-rpm (packaging/fedora/README.md).

macOS and Linux (Homebrew)

packaging/homebrew/muninn.rb installs the prebuilt binary for macOS arm64/x86_64 or Linux arm64/x86_64:

The formula is in the release's packaging tarball, with that release's checksums filled in. Homebrew only installs formulae from a tap (brew install ./muninn.rb fails with "Homebrew requires formulae to be in a tap"), so put it in a local one:

tar -xzf muninn-2.20.0-packaging.tar.gz
brew tap-new --no-git local/muninn
cp packaging/homebrew/muninn.rb "$(brew --repository local/muninn)/Formula/"
brew install local/muninn/muninn
brew developer off      # tap-new turns Homebrew's developer mode on

Once a Homebrew tap is published, brew install from it installs the same thing.

Uninstall: brew uninstall muninn && brew untap local/muninn.

Windows

Release zips hold a portable mnnn.exe for x64 and arm64. In PowerShell (no admin rights needed), download, check, unpack into %LOCALAPPDATA%\Programs\Muninn and add it to your user PATH:

$ver = "2.20.0"; $arch = "x86_64"     # or aarch64
$zip = "muninn-$ver-$arch-pc-windows-gnullvm.zip"
$base = "https://github.com/WeirdBrains/muninn/releases/download/v$ver"
curl.exe -LO "$base/$zip" -LO "$base/SHA256SUMS"
(Get-FileHash $zip).Hash -eq ((Select-String $zip SHA256SUMS).Line -split ' ')[0].ToUpper()   # True
$dest = "$env:LOCALAPPDATA\Programs\Muninn"
Expand-Archive $zip "$env:TEMP\muninn" -Force
New-Item -ItemType Directory $dest -Force | Out-Null
Copy-Item "$env:TEMP\muninn\muninn-$ver-$arch-pc-windows-gnullvm\*" $dest -Recurse -Force
$p = [Environment]::GetEnvironmentVariable("Path", "User")
if ($p -notlike "*$dest*") { [Environment]::SetEnvironmentVariable("Path", "$p;$dest", "User") }

Open a new PowerShell or terminal window (the old one keeps the old PATH) and run mnnn --version. Uninstall: delete %LOCALAPPDATA%\Programs\Muninn and remove it from your user PATH (Settings ▸ System ▸ About ▸ Advanced system settings ▸ Environment Variables). Data lives in %USERPROFILE%\.muninn.

winget (local manifest)

The release's packaging tarball has winget manifests with its checksums filled in. Installing from a local manifest is off by default and must be enabled once in an administrator PowerShell; without it winget only prints "This feature needs to be enabled by administrators":

winget settings --enable LocalManifestFiles     # once, as administrator
tar -xzf muninn-2.20.0-packaging.tar.gz
winget install --manifest packaging\winget\2.20.0

winget adds mnnn to PATH; open a new terminal before running it. Muninn is not in the public winget catalogue yet, so winget install Kommandosaldat.Muninn reports "No package found". Uninstall: winget uninstall --manifest packaging\winget\2.20.0.

From source (any platform)

Needs Rust >= 1.99, a C compiler, perl and make:

cargo install --locked --path .

Uninstall: cargo uninstall muninn.
