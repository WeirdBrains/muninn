Dark shards

The master key can be split among peers you exchanged keys with, so that losing every copy of the 24 words and paper shards is not the end. Shards go to nodes of trusted connections (and your own nodes): mnnn net shard entrust asks before using a node whose user you have not trusted, and the TUI lists only trusted ones.

mnnn net shard entrust --to ben --to cleo --to dev --threshold 2
mnnn net shard list
mnnn net shard restore [--backup net-backup.age] [--recover] [--print-words]
mnnn net shard drop ID          # stop holding someone's shard

What happens

  • Entrust. The master key (from the words, --words-file, 3 --shard files or an exported --master-file; it is never stored, so an unlocked database alone is not enough) is split with Shamir's scheme: one shard per exchange, any threshold of them restore it (default: a majority, at least 2; the peers must be different nodes). Each shard is sealed with your shard password (Argon2id + XChaCha20, bound to the set and shard number) before it leaves, and travels inside the exchange's sealed channel. Peers store a blob they cannot open — a dark shard. An exchange whose short code was never verified asks first, unless its node belongs to a trusted connection.
  • Restore. restore asks your peers for the shards they hold for you, opens them with the shard password and rebuilds the key; it checks the key against the database, or with --recover (default with --backup) sets a new Muninn password. --print-words shows the 24 words again.
  • From nothing. With an exchange backup the node restores its identity and can ask its peers. Each shard is also stored under a claim derived from the shard password, so even a fresh identity can claim it.

The shard password comes from MUNINN_SHARD_PASSWORD, else it is asked for. Keep it apart from the Muninn password. Nothing secret is logged; the history records only which sets went to which exchanges (net.shard.entrust, net.shard.restore) and the holders record net.shard.hold.

In the TUI

Net ▸ Dark shards ▸ Held & entrusted… lists the shards you entrusted and those you hold for others (d drops one you hold). e (or Net ▸ Dark shards ▸ Entrust…) opens the entrust form:

  • Nodes. Every node of a trusted connection is listed (the others are counted as hidden; trust one under Net ▸ Connections…, t); Space picks it. Each picked node gets one shard.
  • Key file. The master key is never stored, so the form reads it from a file: master.key.age or words.txt.age from mnnn keys export --out DIR --only master,words, or your 24 words saved to a plain file (file pass opens .age files). It is checked against this database. The words are never typed in or shown by the TUI.
  • Shard password (twice) and threshold: suggested as a majority (at least 2) and editable. Passwords are masked, cleared after use and never logged.
  • Entrust first checks that every picked node is online (so a set is never half placed), then shows each node's status: ✓ ben: holds shard 1/3.
  • Check restore asks your connections for their shards with the shard password and tells you whether they rebuild this database's key. It changes nothing; to actually recover, use mnnn net shard restore.
